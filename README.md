# Граф зависимостей Python — вариант 14

Практическая работа № 2 по конфигурационному управлению.
Реализованы этапы 1–3: конфигурация, прямые зависимости и рекурсивный DFS.
Результат — текстовый граф, у каждой вершины указана версия пакета.

Для запуска нужен Python 3.10+. Основная программа использует только
стандартную библиотеку: urllib, json, ast и re. Пакеты устанавливать
не нужно. Граф строится собственным кодом, без pip, packaging и networkx.

## Быстрый запуск на Mac

Открой папку проекта в VS Code, затем Terminal → New Terminal:

```bash
sh run.sh --package A --test-repo --repository examples/graph.json
```

Ожидаемый результат:

```text
A@1.0.0 -> B@2.0.0, C@3.0.0
B@2.0.0 -> D@4.0.0
C@3.0.0 -> D@4.0.0
D@4.0.0 -> —
```

Ребро A → B означает: пакет A зависит от B. D — общая зависимость B и C.
Версии тестовых пакетов прочитаны из JSON. Программа их не подставляет сама.

Реальный пакет из PyPI:

```bash
sh run.sh --package requests --repository https://pypi.org/pypi \
  --max-depth 3
```

Версии настоящих пакетов берутся из поля `info.version` JSON API.
При глубине 1 версии прямых зависимостей тоже загружаются, но их
собственные зависимости не раскрываются. На границе явно указана причина
остановки. Номер версии не заменяется ограничением вроде `>=2`.

## Параметры

| Параметр | Назначение | По умолчанию |
|---|---|---|
| `--package` | Имя анализируемого пакета | Обязателен |
| `--repository` | URL JSON API либо путь тестового JSON | `https://pypi.org/pypi` |
| `--test-repo` | Читать тестовый файл вместо сети | Выключен |
| `--max-depth` | Максимальное расстояние от корня, 0–100 | `3` |
| `--stage` | Учебный режим: 1, 2 или 3 | `3` |

```bash
sh run.sh --help
```

## Этап 1 — конфигурация

Аргументы получает argparse. Проверяются имя пакета, URL или тестовый файл,
флаг режима и глубина. При запуске этапа параметры выводятся как ключ-значение.

```bash
sh run.sh --package requests --max-depth 2 --stage 1
```

Примеры ошибок:

```bash
sh run.sh --package 'bad name' --stage 1
sh run.sh --package A --max-depth -1 --stage 1
sh run.sh --package A --repository bad-url --stage 1
sh run.sh --package A --test-repo --repository missing.json --stage 1
```

Ошибки параметров завершают программу с кодом 2 и понятным сообщением.
Схема URL, сервер, порт, пробелы и credentials проверяются отдельно.

## Этап 2 — прямые зависимости

Программа делает HTTP-запрос `<repository>/<package>/json` стандартным
urllib, разбирает JSON и извлекает активные строки `info.requires_dist`.
Условия после точки с запятой проверяются для текущего Python и ОС.
Необязательные extras без явного запроса не включаются.

```bash
sh run.sh --package requests --stage 2
```

На этом этапе выводятся имена прямых зависимостей и ограничения версий,
например `idna <4,>=2.5`. Ограничение описывает допустимые версии;
это не точная версия, которая показывается у вершины на третьем этапе.
Ответы API кешируются в памяти в рамках одного запуска.

## Этап 3 — граф, версии и рекурсивный DFS

DFS углубляется по одной зависимости, затем возвращается и берёт следующую.
`path` хранит текущую цепочку вызовов и позволяет обнаружить цикл.
`expanded_depth` запоминает минимальную глубину раскрытия вершины.
Если позднее найден более короткий путь, узел раскрывается повторно.

Глубина 0 оставляет только корень с его версией. Глубина 1 показывает корень
и прямые зависимости с версиями. На границе зависимости не раскрываются;
для настоящего пакета его метаданные могут быть запрошены ради версии.
Из этого не следует, что граничный пакет является листом.

```bash
sh run.sh --package A --test-repo --repository examples/chain.json \
  --max-depth 1
sh run.sh --package A --test-repo --repository examples/cycle.json
sh run.sh --package A --test-repo --repository examples/shorter_path.json \
  --max-depth 3
```

Цикл не приводит к бесконечной рекурсии. Программа сохраняет его рёбра
и печатает цепочку с версиями участвующих пакетов.
Для ромба D хранится как одна вершина с двумя входящими рёбрами.

## Формат тестового файла

Каждый пакет задаётся объектом с обязательными полями `version` и
`dependencies`. Имена — большие латинские буквы. Все вершины объявляются,
в том числе листья с пустым списком зависимостей.

```json
{
  "A": {"version": "1.0.0", "dependencies": ["B"]},
  "B": {"version": "2.0.0", "dependencies": []}
}
```

Отсутствие версии, пустая версия, неизвестная ссылка, повтор зависимости
или неверный тип поля считаются ошибкой. Старый формат `"A": ["B"]`
не принимается, поскольку не содержит версии.

- `examples/graph.json` — ромб с общей зависимостью.
- `examples/chain.json` — последовательная цепочка.
- `examples/cycle.json` — циклические зависимости.
- `examples/isolated.json` — корень без зависимостей.
- `examples/shorter_path.json` — длинный и короткий путь к одному узлу.

## Проверки оформления и сложности

```bash
make test
```

Автономные unittest не требуют сети и сторонних библиотек.
Они проверяют CLI, метаданные, markers, DFS, циклы, глубину и версии.

Инструменты проверки кода устанавливаются отдельно:

```bash
python3 -m pip install -r requirements-dev.txt
make check
```

- `check_style.py`: строки Python до 80 символов, файлы до 1000 строк,
  функции до 40 строк, до 7 аргументов, наличие docstrings.
- `check_complexity.py`: Radon 6.0.1, сложность каждого блока до 10.
  Проверяются src, tests и scripts, включая методы и вложенные функции.
- Ruff: формат имён и импортов, ошибки Python и дополнительная проверка C90.

Одной проверки Ruff недостаточно: Radon также учитывает логические
операторы и некоторые конструкции, которые C90 считает иначе.
[Полный результат проверки](docs/complexity.json) сохранён в репозитории.
Radon и Ruff применяются только для контроля кода; в сборе зависимостей
основной программой они не участвуют.

## Структура и функции

- `src/depviz/config.py` — аргументы и независимые проверки параметров.
- `network.py`, `pypi.py` — собственный HTTP-клиент и кеш метаданных.
- `requirements.py`, `markers.py`, `versions.py` — строки зависимостей,
  условия окружения, сравнение числовых версий и проверка подписей версий.
- `testrepo.py` — локальный тестовый репозиторий с версиями.
- `graph.py` — рекурсивный DFS, циклы, глубина и текстовый граф.
- `cli.py` — выбор одного из трёх этапов и обработка ошибок.
- `tests/` — тесты; `scripts/` — проверки оформления и сложности.

[Описание функций](docs/API.md) · [Подготовка к защите](docs/DEFENSE_RU.md).

Сборка не требуется. Скрипт `run.sh` добавляет src в PYTHONPATH и
запускает `python3 -m depviz`. При желании CLI можно установить через
`python3 -m pip install .`, но для запуска из папки проекта это не нужно.

## Ограничения

Читается последняя опубликованная версия каждой вершины из JSON API.
Ограничения Requires-Dist сохраняются, но полный resolver с backtracking
и подбором единого совместимого набора релизов не реализован.
Показанные версии — реальные версии метаданных, а не обещание, что pip
выберет именно этот набор при установке.

Поддерживается JSON API PyPI, не HTML simple-index. Неизвестные markers,
активные extras, прямые URL и динамические зависимости дают явную ошибку.
Сравнение версий в markers поддерживает стабильные числовые релизы;
полный синтаксис нестандартных версий не реализован.

Эта версия ограничена первыми тремя этапами. Порядок загрузки,
PlantUML, создание изображений и Java в неё не входят.
