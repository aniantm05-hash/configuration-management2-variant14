# Функции первых трёх этапов

## __init__.py

## __main__.py

## cli.py

- `repository_for` — Выбрать реальный JSON API или локальный тестовый репозиторий.

- `execute` — Выполнить поведение выбранного учебного этапа.

- `main` — Завершить CLI ненулевым кодом при диагностируемой ошибке.

## config.py

- `package_name` — Проверить имя пакета.

- `depth_value` — Проверить целую глубину от нуля до установленного предела.

- `parser` — Создать параметры только первых трёх этапов.

- `validate_test_source` — Тестовый режим требует заглавное имя и существующий файл.

- `validate_url_shape` — Проверить схему, сервер и корректность порта URL.

- `validate_url_details` — Отклонить credentials и параметры, меняющие путь JSON API.

- `validate_source` — Выбрать проверку файла либо сетевого репозитория.

- `read_options` — Разобрать параметры и вывести ошибки средствами argparse.

## graph.py

- `record_cycle` — Запомнить обнаруженный цикл один раз.

- `build_graph` — Пройти граф DFS с рекурсией и повторным раскрытием коротких путей.

- `package_label` — Одинаково подписать корень, листья и участники цикла.

- `adjacency_line` — Отличить подтверждённый лист от границы анализа.

- `adjacency_text` — Показать список смежности с точными версиями и циклами.

- `visit` — Прочитать версию, затем раскрыть разрешённые глубиной рёбра.

## markers.py

- `environment` — Вернуть окружение текущего интерпретатора, без запрошенных extras.

- `operand` — Разрешить только строковые литералы и известные имена.

- `compare` — Вычислить одно сравнение marker, не исполняя Python-код.

- `evaluate` — Рекурсивно разобрать and/or и сравнения; вызовы запрещены.

- `marker_active` — Проверить marker, не скрывая неизвестный синтаксис.

## network.py

- `fetch_json` — Скачать ограниченный JSON-ответ и объяснить сетевые ошибки.

## pypi.py

- `__init__` — Сохранить базовый URL и функцию HTTP-запроса.

- `info` — Загрузить метаданные пакета не более одного раза за запуск.

- `version` — Прочитать настоящую версию из info.version.

- `dependencies` — Разобрать активные runtime-зависимости из Requires-Dist.

- `_info` — Проверить структуру JSON и оставить необходимые поля.

## requirements.py

- `normalize` — Нормализация имён дистрибутивов по правилам Python index.

- `parse_requirement` — Отфильтровать необязательные зависимости и разобрать активные.

- `parse_dependencies` — Получить активные runtime-зависимости текущего окружения.

## testrepo.py

- `validate_package` — Разрешить только имена из заглавных латинских букв.

- `validate_children` — Проверить тип списка, повторения и существование зависимостей.

- `validate_record` — Каждая запись обязана задавать version и dependencies.

- `validate_graph` — Проверить граф до начала обхода, включая отдельные вершины.

- `read_graph` — Прочитать UTF-8 JSON и объяснить ошибку формата или доступа.

- `__init__` — Сохранить проверенные записи без вымышленных значений.

- `record` — Объяснить отсутствие пакета в тестовом репозитории.

- `version` — Получить явную версию пакета, в том числе на границе глубины.

- `dependencies` — Вернуть прямые зависимости заданной записи.

## versions.py

- `validate_version` — Принять непустую версию без пробелов и управляющих символов.

- `release` — Разобрать стабильный релиз; prerelease не выбирать автоматически.

- `numeric_compare` — Сравнить релизы с дополнением нулями: 1.0 равно 1.

- `single_match` — Поддержать обычные ограничения, wildcard и совместимый релиз.

- `satisfies` — Проверить все ограничения, соединённые запятыми.
